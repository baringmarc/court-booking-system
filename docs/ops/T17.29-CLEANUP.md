## Tooling

- `supabase/functions/_shared/venueHistoryPurge.ts`: `validateManifest`, `backupSql`, `purgeSql`, `removeProofFiles`.
- `scripts/purge-venue-history.mjs`: the operator CLI (`backup-sql`, `sql`, `files [--remove-proofs]`). The SQL steps refuse unless the CLI is linked to the manifest's project; `files` refuses a URL for another project and a backup directory inside the repo.
- `purgeSql` is one `do` block: for each venue it locks the venue and its courts, refuses (`venue_not_found`, `venue_slug_mismatch`, `venue_protected`, `invoiced_charge`, `manifest_mismatch`) unless the bookings, payments, charges, open-play sessions, proof paths and the five counts match the manifest exactly, then deletes open play (its courts cascade) and the bookings, moved bookings first (payments, checkouts, emails, changes, guest tokens and charges cascade), and checks no history is left (`purge_incomplete`). Any refusal rolls everything back.
